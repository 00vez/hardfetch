hardfetch – Protokoll & Fortschritt

Projektziel

  • Windows-Konsolentool im Stil von neofetch: kompakte Systeminformationen (OS, Host, Kernel, Uptime, Shell, CPU, Speicher, GPU, Storage) in einem Durchlauf, ohne Logo/Rahmen.
  • C11 für C-Dateien, C++17 nur für WMI/COM-Module; MSVC /MT (statisch), keine externen Laufzeit- oder Bibliotheksabhängigkeiten.

Kontext und Ausgangslage

  • Version 0.1.0. Windows 11, Build 26200 (25H2). Einzelnes CMake-Target, flaches src/.
  • Adminrechte nötig für: ICMP-Ping (--net), NVMe-Temp, CPU-Power, WMI-Thermalzonen (CPU-Temp). Netzwerksektion nur mit --net.
  • Toolchain: VS 2022 BuildTools unter C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools; Generator Visual Studio 17 2022 (MSBuild), kein Ninja.
  • Bekannte Einschränkungen (aus AGENTS.md): CPU zeigt Base (4.2 GHz) statt Boost (5.05 GHz) wegen PDH auf AMD Ryzen (CPPC); AMD-iGPU-VRAM 0 (WMI AdapterRAM); Temp N/A bei manchen Ryzen (k10temp nicht via WMI erreichbar).
  • src/ip_addr.c wird kompiliert, aber print_ip_info() wird nirgends aufgerufen (toter Code).

Architektur und Entscheidungen

  • Windows-spezifische Module: cpu_temp.cpp, memory_spd.cpp, gpu.cpp nutzen WMI/COM (C++); GPU zusätzlich NVIDIA via dynamischem NVML (LoadLibraryA("nvml.dll")). Kopfzeilen mit extern "C".
  • Build-Quirks: gemischtes Target mit LINKER_LANGUAGE C; leeres CMAKE_CXX_IMPLICIT_LINK_LIBRARIES gegen libstdc++.
  • Geplanter Port macOS: Design steht, noch nicht umgesetzt. Geteilte POSIX-Schicht (src/posix/) für macOS und Linux/WSL2.
  • WSL2/Linux-Port (Code): Plattformweiche in CMakeLists.txt, src/main.c + src/output.c portabel, 13 POSIX-Module (src/posix/*.c); --net repurposed (kein Admin mehr), Durchsatz/Ping entfernt. Build-Verifikation in WSL2 ausstehend.

Akzeptanzkriterien

  • Kurzform -h/-v funktionieren wie --help/--version (verifiziert am gebauten Binary).
  • hrf ist als Alias in der PowerShell-Profildatei verfügbar und ruft hardfetch.exe (verifiziert).
  • Ausgabeverzögerung nach den ersten Sektionen analysiert und behoben: Gesamt-Wall-Zeit 0,51–0,68 s → 0,22 s (per Measure-Command, 5 Läufe). Ursachen und Fixes siehe Protokoll Session 2.
  • Netz-Sektion hinter -n/--net (statt immer): Standardlauf ohne Netz, mit Flag erscheinen Interfaces + öffentliche IP. Verifiziert am Build.
  • Alter Durchsatz-/Ping-Abschnitt (network.c + ICMP) entfernt; --net repurposed für die neue Netz-Sektion (kein Admin mehr nötig).
  • WSL2/Linux-Port: Code vollständig (src/posix/*.c + CMakeLists-Plattformweiche), aber nicht aus Build verifiziert (kein Linux-Compiler in dieser Umgebung). Erste WSL2-cmake-Build als Verifikationsschritt nötig.
  • Toter Code ip_addr.c aufgelöst: print_ip_info() ist jetzt eingebunden und listet alle aktiven Interfaces (vorher: nur ein "bestes" Interface, nirgends aufgerufen).
  • Farbschema einheitlich: bestehende ANSI-Codes (\x1b[90m grau, \x1b[92m grün, \x1b[97m weiß, \x1b[1;90m fett grau) sind plattformunabhängig; macOS/WSL2-Port übernimmt sie identisch. Kein Auto-Strip bei Pipe.
  • macOS-Build mit denselben Sektionen wie Windows (Best-Effort, fehlende Werte als N/A).

Protokoll vom 30.08.2026 (5. Session) — Version 0.2.0, WSL2 verifiziert

Befund und Fixes

  • GPU in WSL2 war N/A: WSL2 exponiert kein /sys/class/drm/card* (nur version); GPU läuft über /dev/dxg-Paravirtualisierung. Per WSL-Probe bestätigt: /usr/lib/wsl/lib/libnvidia-ml.so.1 (595.71.01) existiert. Fix: src/posix/gpu_posix.c lädt NVML dynamisch (dlopen, Pfad: WSL → x86_64 → libname) und liefert Name/Core/Mem/Load/VRAM/Temp/Power wie Windows; DRM bleibt Fallback für natives Linux (NVIDIA-Cards dort übersprungen). Dazu dl in Linux-Linkliste.
  • Public N/A in WSL2: Rennbedingung — main kehrte zurück, während der detachte Fetch-Thread noch lief; Prozess-Exit killte ihn vor g_done. Fix: src/posix/public_ip_posix.c wartet in public_ip_print() gebunden über pthread_cond_timedwait (1 s, sofort wenn fertig).
  • CPU-Details WSL2: Kernzählung off-by-one (17 → 16 auf 7800X3D), -Core Processor-Suffix abgeschnitten (wie Windows).
  • Version 0.1.0 → 0.2.0: src/main.c, CMakeLists.txt (project VERSION), Win-UA-String in src/public_ip.c.

Implementierung

  • Linux-Komfortzapf: WSL-~/.zshrc bekommt Funktion hrf(), die inkrementell cmake --build build-wsl ausführt und dann das Binär startet — analog zum Windows-Alias hrf. Flag-Argumente (-n, -v, …) werden durchgereicht.

Verifikation

  • Windows: Release-Build Exit 0, hardfetch.exe -v → hardfetch v0.2.0.
  • WSL2 (selbst gebaut und ausgeführt): ./build-wsl/hardfetch -n → eth0 172.26.98.227/20 + Public 178.190.95.110; GPU-Detail-Zeile RTX 5070 korrekt; Build BUILD_OK. zsh -ic 'hrf' → v0.2.0, hrf -n → Netz-Sektion.
