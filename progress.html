hardfetch – Protokoll & Fortschritt

Projektziel

  • Windows-Konsolentool im Stil von neofetch: kompakte Systeminformationen (OS, Host, Kernel, Uptime, Shell, CPU, Speicher, GPU, Storage) in einem Durchlauf, ohne Logo/Rahmen.
  • C11 für C-Dateien, C++17 nur für WMI/COM-Module; MSVC /MT (statisch), keine externen Laufzeit- oder Bibliotheksabhängigkeiten.

Kontext und Ausgangslage

  • Version 0.2.4. Windows 11 25H2 (26200), macOS 26.5 (Darwin 25.5, Apple M4), WSL2 Ubuntu. Einzelnes CMake-Target, src/ + src/posix/ (Apple/Linux).
  • Netzwerksektion nur mit -n/--net, Public-IP via WinHTTP (Win) / POSIX-Socket (Linux/macOS). Kein ICMP mehr, kein Admin nötig.
  • Toolchain: VS 2022 BuildTools 17 2022 (MSVC /MT) — Windows; AppleClang 21.0.0 — macOS; gcc — WSL2/Ubuntu. Kein Ninja, kein Redistributable.
  • Bekannte Einschränkungen (aus AGENTS.md): AMD Ryzen Boost via PDH 100% (CPPC) — nicht messbar im User-Mode; AMD-iGPU VRAM 0; k10temp N/A.

Architektur und Entscheidungen

  • Windows-Module (C++ WMI/COM): cpu_temp.cpp, memory_spd.cpp, gpu.cpp (NVML dynamisch via LoadLibraryA). Header mit extern "C".
  • Build-Quirks: LINKER_LANGUAGE C, leeres CMAKE_CXX_IMPLICIT_LINK_LIBRARIES gegen libstdc++.
  • POSIX-Schicht src/posix/ (Apple + Linux): 16 Module — os_info/host/kernel/uptime/shell/gpu/cpu/cpu_temp/memory/memory_spd/storage/ip_addr/public_ip/apple_pmgr/apple_smc/battery + HID-Fallback apple_hid_cpu_temp in cpu_temp_posix.c. Plattformweiche if(WIN32) … else() in CMakeLists.txt.
  • Apple-Silicon Besonderheiten: CPU/GPU-Takt via pmgr voltage-states*-sram (CFData, Hz/kHz-Heuristik), Temp primär AppleSMC IOConnectCallStructMethod (Selector 2, Sub 5/8/9, 80-Byte SmcParam, flt/sp78/fpe2/ui32), Fallback IOHIDEventSystemClient privat (0xff00/5, kIOHIDEventTypeTemperature=15, 47 Sensoren, max PMU t*), Load via host_processor_info 200ms.
  • WSL2/Linux verifiziert: build-wsl/hardfetch per cmake -B build-wsl && cmake --build build-wsl (WSL-Ubuntu, gcc, pthread/dl).
